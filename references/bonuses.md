# Bonuses

Use bonuses to make valuable components visible, resolve objections, and widen the value-price gap without discounting the core offer.

Book basis: chapter 14, PDF pp. 145–153. Read [knowledge-bonuses.md](knowledge-bonuses.md) for explanation, source nuances and examples. See [book-map.md](book-map.md) for citation conventions. Distinguish presentation labels from fulfillment dependencies.

## 1. Decide core versus bonus

Keep a component reliably included when the primary promise cannot be delivered without it. It may be highlighted separately in presentation, as in the book, but do not make it genuinely optional or withdraw it while keeping the same promise.

Use a component as a bonus when it:

- Resolves a distinct objection.
- Solves the buyer's next problem.
- Creates a noticeable "wow" moment.
- Can stand alone conceptually.
- Increases speed, certainty, or ease.
- Is valuable and distinct; if also required for the core promise, keep that fulfillment dependency explicit.

Do not label essential service as optional merely to inflate the bonus stack.

## 2. Generate bonus candidates

For every major obstacle, ask:

- What tool would save the buyer time?
- What checklist would prevent a predictable mistake?
- What template, script, calculator, configuration, or swipe file would reduce effort?
- What orientation or quick-start asset would produce a fast win?
- What adjacent need appears immediately after success?
- What limited access, review, or support would increase confidence?
- What existing workshop, recording, or asset directly solves this obstacle?

Prefer tools, checklists, defaults, and ready-to-use assets over additional training when they produce the same result with less effort.

## 3. Build each bonus

For every bonus, define:

| Field | Requirement |
|---|---|
| Benefit-led name | Make the resolved obstacle or desired result recognizable. |
| Objection or next problem | State exactly why this bonus exists. |
| What it is | Describe the format and contents plainly. |
| How it is used | Show when and how the buyer applies it. |
| Origin | Explain a real discovery, recurring problem, or creation effort; do not invent a backstory. |
| Value lever | Identify whether it improves belief, speed, ease, or outcome. |
| Proof | Provide relevant evidence, demonstration, or rationale. |
| Expected benefit | Describe the support it provides without inflating the claim. |
| Credible standalone value | State a defensible basis or omit the number. |
| Delivery cost and capacity | Confirm it remains profitable and available. |

Name core components and bonuses consistently. A component that sounds generic will be undervalued even when it is useful.

## 4. Value bonuses credibly

Use one or more defensible anchors:

- Actual standalone selling price.
- Comparable replacement cost.
- Verified partner retail price.
- Reasonable value of time saved.
- Cost of a common mistake avoided.
- Cost of professional help otherwise required.

Do not invent inflated "total values." Explain the basis. If no credible monetary basis exists, describe utility instead of assigning a price.

## 5. Present bonuses

For a public or one-to-many presentation, use this implementation structure; the book explicitly leaves full group-selling instruction outside its scope:

1. Establish the core offer and price.
2. Present bonuses one at a time.
3. Connect each bonus to a known obstacle.
4. Explain use, benefit, proof, and value.
5. Summarize the complete stack.

For one-to-one sales:

- Ask for the decision on the core offer.
- If the buyer accepts, reveal any genuine surprise bonus to reinforce the decision.
- If the buyer hesitates, add only a bonus that directly resolves the stated obstacle, then ask again.

Do not use irrelevant bonuses to pressure a buyer.

## 6. Use partner bonuses

Adjacent businesses may contribute products, services, access, or discounts when the arrangement benefits the customer and both businesses.

Verify:

- The partner is reputable and not a conflicting competitor.
- The customer understands any referral or affiliate relationship.
- The retail value and availability are real.
- Privacy, insurance, professional, anti-kickback, inducement, licensing, and disclosure rules permit the arrangement.
- The bonus does not undermine the core outcome.

Do not exchange customer data without authority.

## 7. Maintain a bonus bank

Record reusable assets by:

- Obstacle solved.
- Buyer segment.
- Format.
- Value lever improved.
- Evidence.
- Standalone value basis.
- Fulfillment cost.
- Capacity or expiration.
- Best point of presentation.

Reuse only bonuses relevant to the current offer. A larger stack is not automatically a better stack.

## Bonus deliverable

Provide:

1. Core-versus-bonus decisions.
2. Ranked bonus table.
3. Presentation order and script.
4. Credible valuation basis.
5. Scarcity or urgency, if real.
6. Partner, compliance, and capacity risks.
